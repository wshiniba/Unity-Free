# 开发推进框架

更新时间：2026-06-22
当前适用目标：第一张完整样板关

## 1. 这份文档解决什么问题

你当前最大的风险不是没想法，而是：

- 新点子来得太快
- 系统同时开太多
- 某些功能做到一半就切走
- 隔几天回来看，不知道下一步先做什么

所以这份框架只做一件事：把“想到的内容”和“现在必须做的内容”分开。

## 2. 当前北极星目标

当前版本只盯一个目标：

**做出一张完整可玩的样板关，跑通机动、战斗、处决、成长、Boss。**

只要一个新想法不能直接帮助这个目标，它就不应该插队开发。

## 3. 四层任务结构

### 第 1 层：当前里程碑

只有一个。

- 第一张完整样板关

### 第 2 层：本周锁定项

每周最多锁 3 个主任务，超过 3 个基本就会分心。

建议当前固定为：

1. 投掷手感定版
2. 首个样板关灰盒跑通
3. 三类小怪模板落地

### 第 3 层：候选任务池

这些任务重要，但不允许在当天临时插队：

- 升级 UI 最小版
- 玩家死亡流程
- 配置表导入
- Boss 原型整理
- 处决表现补强
- HUD 整理

### 第 4 层：创意池

所有临时想到的新点子都扔这里，不直接开工。

## 4. 新点子收纳规则

每次冒出新点子，只写 6 行：

- 点子名：
- 它解决什么问题：
- 影响哪个系统：
- 最小实现是什么：
- 现在要不要做：
- 不做会不会卡当前里程碑：

判断规则：

- 会卡当前里程碑：进候选任务池，评估优先级
- 不会卡当前里程碑：进创意池，先冻结

## 5. 功能准入规则

只有满足下列任意一条的新功能，允许进入“本周锁定项”：

1. 它能直接提升触手核心手感
2. 它能补完首关流程断点
3. 它能让敌人/Boss 玩法真正可测
4. 它能让升级或掉落循环真正闭环

否则不准插队。

## 6. 建议的开发顺序

### 阶段 A：把可玩骨架跑通

- 投掷手感定版
- 小怪模板 01、02、03 可打通
- 样板关灰盒完成
- Boss 房流程打通

### 阶段 B：把循环补闭环

- 升级 UI 最小版
- 掉落与资源消耗跑通
- 玩家死亡流程补全
- HUD 最小版稳定

### 阶段 C：把表现补到能展示

- 小怪受击、死亡、处决表现加强
- 投掷、弹反、处决特效补足
- 场景第一轮美术替换
- Boss 第一轮包装

### 阶段 D：把数据变得可维护

- Excel/CSV 配置表
- 掉落表正式化
- 升级成本与敌人参数统一配置

## 7. 每次开发会话的固定流程

### 开工前

先写清楚今天只做什么：

- 今天主任务：
- 验收条件：
- 不做的事：

例子：

- 今天主任务：把敌人投掷速度公式调到稳定可用
- 验收条件：轻敌、重敌、场景物都能稳定甩出且不离谱
- 不做的事：不碰升级 UI，不碰 Boss 美术

### 开发中

如果冒出新点子，不改计划，只记到创意池。

### 收工前

必须补 3 行：

- 今天完成了什么：
- 当前卡点是什么：
- 下次开工第一步是什么：

这样下次回来不会断线。

## 9. 完成定义

### 一个功能算完成，至少要满足

- 能实际进场景测试
- 有明确输入和结果
- 不依赖口头记忆才能复现
- 关键参数有文档记录
- 不会在下次会话里看不懂

### 一个关卡房间算完成，至少要满足

- 玩家知道这里要做什么
- 这里主要测试一个机制
- 从入口到出口流程清晰
- 锚点、敌人、奖励位置都可解释

### 一个美术任务算完成，至少要满足

- 读图不影响玩法
- 关键交互可识别
- 不会和碰撞或可抓取物混淆

## 12. 最后一条硬规则

在样板关完成前，任何新点子都不能同时触发“新系统 + 新美术包 + 新 UI + 新敌人”四件事。

一次只推进一个主问题，开发速度才会真正快起来。
