## Player Attack

- Added `PlayerAttack`.
- Pressing `F` triggers attack.
- Player has four directional hitboxes:
  - `HitBox_Right`
  - `HitBox_Left`
  - `HitBox_Up`
  - `HitBox_Down`
- Hitboxes are tagged as `PlayerHitBox`.
- Ground attack direction is based on player facing.
- Air attack direction is based on velocity:
  - If horizontal speed is greater than or equal to vertical speed, use left/right hitbox.
  - Otherwise use up/down hitbox.
  - If airborne speed is too low, fall back to facing direction.
- Hitbox active duration can use the hitbox Animator clip duration.
- Hitbox animation is restarted when the hitbox becomes active.
- Attack damage is speed-based:
  - Uses base damage.
  - Uses player current speed.
  - Uses a reference speed, usually `OdmController.maxSpeed`.
  - Uses a configurable max speed damage bonus and exponent.
- A debug option can log current speed and predicted damage every frame.

## Boss System

### Current Boss States

`BossBattleState` currently contains:

- `Dormant`: Boss battle not started.
- `Intro`: Battle entry / short delay after arena lock.
- `AttackPattern`: Boss is invulnerable and performs attacks.
- `Vulnerable`: Boss can be damaged.
- `HitReact`: Boss reacts to hit, hides, clears hazards, repositions.
- `Defeated`: Boss defeated, hazards cleared, arena unlocked.

### Boss Flow

Current battle loop:

```text
Dormant
-> player enters BossArena
-> Intro
-> AttackPattern
-> Vulnerable
-> if not hit: reposition and continue
-> if hit: HitReact, hide, clear hazards, reposition, continue
-> if health reaches 0: play hurt, then Defeated
```

### Boss Attack Patterns

Current patterns are selected by `patternIndex % 3`:

- `RadialBurstPattern`
  - Fires circular bullet rings.
- `TrapFieldPattern`
  - Spawns warning traps, then active traps.
- `HookAnchorAndAimedShotsPattern`
  - Spawns temporary hookable anchors.
  - Fires aimed volleys toward player.

### Boss Animation

Boss Animator parameters currently planned/used:

- Bool `isHurt`
  - Controls hurt animation.
- Bool `isAttack`
  - Controls attack animation while firing/performing patterns.

Boss death behavior was changed so the Boss does not instantly disappear on lethal damage. It plays hurt first, then enters defeated behavior.

### Boss Hit And Damage

- Boss is only damageable during `Vulnerable`.
- Boss detects `PlayerHitBox`.
- Boss reads `PlayerAttack.CurrentAttackDamage`.
- Boss calculates hit direction and hit speed ratio from the player's Rigidbody2D.
- Boss triggers `HitFeedback` when damaged.

### Boss Arena

`BossArenaController` handles:

- Player entering the arena trigger.
- Starting the Boss battle.
- Enabling lockdown walls.
- Unlocking the arena after Boss defeat.

### Boss Hazards

- `BossProjectile`
  - Moves in a direction.
  - On player hit, applies knockback and logs damage.
- `BossTrap`
  - Warning phase, then active trigger phase.
  - Applies knockback and logs damage.
- `HookableBossAnchor`
  - Temporary hookable point.
  - Auto-destroys after lifetime.
- `BossHazardUtility`
  - Finds player `OdmController`.
  - Clears player velocity and applies knockback.
  - Current player damage is only logged, not connected to a full player health system.

## Hit Feedback

Added `HitFeedback` for Boss hit feedback.

Current features:

- Hit stop:
  - Temporarily changes `Time.timeScale`.
  - Uses realtime wait so the pause duration is stable.
  - Does not extend attack animation directly.
- Camera shake:
  - Uses Cinemachine Impulse.
  - Requires `CinemachineImpulseSource` on the feedback object.
  - Requires `CinemachineImpulseListener` on the Virtual Camera.
  - Can be horizontal-only.
  - Can scale shake by player hit speed.
- Important Inspector parameters:
  - `enableHitStop`
  - `hitStopTimeScale`
  - `hitStopDuration`
  - `enableCameraShake`
  - `cameraShakeForce`
  - `scaleShakeByHitSpeed`
  - `maxSpeedShakeMultiplier`
  - `horizontalOnlyShake`

Manual setup guidance:

- Add `HitFeedback` to Boss.
- Assign or confirm `CinemachineImpulseSource`.
- Add `CinemachineImpulseListener` to the active Virtual Camera.
- Drag the Virtual Camera / listener into `HitFeedback` where possible.
- BossController keeps only the reference to `HitFeedback`; feedback tuning should mainly happen on `HitFeedback`.

## Player Physics Tuning

ODM physics was adjusted to use state-based gravity and damping while still relying on Unity Rigidbody2D.

Important fields added/planned in `OdmController`:

- Rigidbody override:
  - `overrideRigidbodySettings`
  - `bodyMass`
  - `bodyLinearDamping`
  - `bodyGravityScale`
- State physics:
  - `enableStatePhysics`
  - `groundedGravityScale`
  - `airborneGravityScale`
  - `pullingGravityScale`
  - `swingingGravityScale`
  - `burstPullGravityScale`
  - `hoveringGravityScale`
  - `groundedDamping`
  - `airborneDamping`
  - `pullingDamping`
  - `swingingDamping`
  - `burstPullDamping`
  - `hoveringDamping`
  - `gravityChangeSpeed`
  - `dampingChangeSpeed`
- Falling:
  - `limitFallSpeed`
  - `maxFallSpeed`
- High-speed gravity:
  - `reduceGravityAtHighSpeed`
  - `highSpeedGravityMinMultiplier`
  - `highSpeedGravityReference`

Recommended baseline:

```text
Grounded Gravity Scale: 2
Airborne Gravity Scale: 3
Pulling Gravity Scale: 1.1
Swinging Gravity Scale: 1.5
Burst Pull Gravity Scale: 0.35

Grounded Damping: 0.5
Airborne Damping: 0.03
Pulling Damping: 0
Swinging Damping: 0.02
Burst Pull Damping: 0

Max Fall Speed: 28
High Speed Gravity Min Multiplier: 0.55
High Speed Gravity Reference: 30
```

Clarification:

- All damping parameters ultimately affect `Rigidbody2D.linearDamping`.
- They have the same physical mechanism, but are split by player state so ground, air, pulling, swinging, burst pull, and hover can feel different.

## External Config Discussion

Created an example Excel config table:

```text
Assets/Configs/PlayerPhysicsConfig.xlsx
```

Purpose:

- Demonstrate how physics parameters could be organized as data.
- Not currently read by Unity.

Recommended future external-data flow:

```text
Excel edit source
-> export CSV or JSON
-> put file in Resources or StreamingAssets
-> Unity reads TextAsset or file
-> parse into config object
-> apply to OdmController
```

Preferred machine-readable table shape:

```text
key,value,type,description
airborneGravityScale,3,float,normal airborne gravity
airborneDamping,0.03,float,normal airborne damping
pullingGravityScale,1.1,float,pulling gravity
maxFallSpeed,28,float,max fall speed
limitFallSpeed,true,bool,whether fall speed is clamped
```

Recommended architecture if implemented later:

- `PlayerPhysicsConfig`
  - Stores parsed config data.
- `PlayerPhysicsConfigLoader`
  - Reads and parses CSV/JSON.
- `OdmController`
  - Receives config and applies values.

## Current Expansion Direction

For Boss expansion, the recommended structure is:

```text

BossPhase: current health/phase stage
BossPattern: selected attack move
```

Likely next improvements:

- Separate attack patterns out of `BossController`.
- Add phase thresholds, such as 70% and 40% health.
- Replace temporary primitive visuals with prefabs.
