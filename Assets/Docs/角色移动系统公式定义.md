# 角色移动系统公式定义

更新时间：2026-07-09

适用对象：

- 主测试角色：`Assets/Prefab/Player 2.prefab`
- 主测试场景：`Assets/Scenes/TestScence.unity`
- 主要脚本：`Assets/Scripts/触手/OdmController.cs`

这份文档的目的不是记录“当前填了哪些 Inspector 数字”，而是定义角色移动系统应该遵守的公式、参数层级和地图设计推导方法。后续所有手感调整、地图灰盒尺寸、脚本重构，都应优先对齐这里的模型。

## 1. 核心结论

角色移动应采用“动作游戏可控物理”模型，而不是完整真实物理模拟。

绳索运动的核心不是软体绳索，也不是 Joint2D 真实摆锤，而是：

```text
绳索长度约束 + 圆周切向运动 + 可控牵引加速度 + 全局速度上限
```

这样做的原因：

- 玩家需要可控、可复现、可调试的手感。
- 地图设计需要能从速度和飞行时间反推平台距离。
- 完整物理绳索会受碰撞、双绳、弯折、质量和 Solver 误差影响，难以稳定定版。
- 当前代码已经接近这个模型：超过绳长时把玩家压回绳长边界，并移除远离锚点的径向速度。

所以后续不要追求“真实绳索”，而要追求“公式可解释、数值可复现、地图可反推”。

## 2. 坐标和基础量

Unity 2D 坐标：

- X：水平，向右为正。
- Y：垂直，向上为正。
- Unity 默认重力加速度：`g0 = 9.81`。
- 角色质量当前按 `m = 1` 设计；若以后改质量，所有 Force 型参数都应改成加速度参数，再由 `Force = mass * acceleration` 派生。

速度记号：

```text
p = 角色位置
v = 角色速度
a = 角色加速度
dt = FixedUpdate 步长
```

## 3. 状态定义

当前移动状态保留 6 类，但后续公式只允许分成 4 个物理模式：

| OdmState | 物理模式 | 说明 |
| --- | --- | --- |
| Grounded | 地面模式 | 地面输入直接追目标水平速度。 |
| Airborne | 空中模式 | 不主动改水平速度，只受重力、冲刺、外力和速度上限影响。 |
| Shooting | 空中/地面过渡 | 绳头飞行中；如果在地面可继续地面移动。 |
| Swinging | 绳索圆周模式 | 有锚点，绳索只限制最大长度，重力提供切向加速。 |
| Pulling | 绳索牵引模式 | 有锚点且按住 Q，向锚点施加牵引加速度。 |
| Hovering | 绳索锁长模式 | 锁定进入悬停时的绳长，只允许切向重力/切向输入，不允许继续远离锚点。 |

重要约束：

- `Shooting` 不应拥有独立重力手感，除非后续证明有必要。
- `Pulling` 不应绕开速度上限。
- `Hovering` 不是无物理悬空，而是锁长后的切向运动。

## 4. 最小主参数集

为了减少参数数量，后续应把 Inspector 分成“主设计参数”和“派生参数”。

### 4.1 主设计参数

这些参数可以由设计直接决定：

| 参数 | 含义 | 当前 Player 2 |
| --- | --- | ---: |
| `groundMaxSpeed` | 地面最大水平速度 | 20 |
| `groundAccelTime` | 地面从 0 到满速的时间 | 0.2 秒 |
| `jumpHeight` | 纯跳最高高度 | 约 2.65 |
| `jumpApexTime` | 到达跳跃顶点时间 | 约 0.21 秒 |
| `airGravity` | 空中重力加速度 | 117.72 |
| `maxFallSpeed` | 最大下落速度 | 60 |
| `maxCableLength` | 最大绳长/最大连接距离 | 40 |
| `ropeGravity` | 摆荡模式重力加速度 | 107.91 |
| `pullAcceleration` | Q 牵引加速度 | 300 |
| `swingAssistAcceleration` | A/D 摆荡辅助加速度 | 20 |
| `maxPlayerSpeed` | 玩家总速度硬上限 | 70 |

### 4.2 派生参数

这些不应长期作为独立设计项：

```text
groundAcceleration = groundMaxSpeed / groundAccelTime
jumpSpeed = 2 * jumpHeight / jumpApexTime
airGravity = 2 * jumpHeight / jumpApexTime^2
airborneGravityScale = airGravity / g0
pullForce = bodyMass * pullAcceleration
swingForce = bodyMass * swingAssistAcceleration
```

当前代码还没有全部按派生参数实现，但设计上应按这个关系理解。

## 5. 地面移动公式

地面移动使用目标速度追踪：

```text
targetVx = inputX * groundMaxSpeed
vx = MoveTowards(vx, targetVx, groundAcceleration * dt)
```

其中：

```text
groundAcceleration = groundMaxSpeed / groundAccelTime
```

当前 Player 2：

```text
groundMaxSpeed = 20
groundAcceleration = 100
groundAccelTime = 20 / 100 = 0.2 秒
从静止到满速距离 = V^2 / (2a) = 20^2 / 200 = 2 单位
```

地图意义：

- 地面起步非常快，2 单位内就能接近满速。
- 不能用很短平台强行制造“起步不够”的难度。
- 地面纯跑 1 秒约 20 单位。

## 6. 跳跃和空中公式

跳跃应由“跳高”和“到顶时间”定义，而不是直接凭感觉填 `jumpSpeed` 和 `airborneGravityScale`。

设计公式：

```text
airGravity = 2 * jumpHeight / jumpApexTime^2
jumpSpeed = 2 * jumpHeight / jumpApexTime
```

反推当前 Player 2：

```text
jumpSpeed = 25
airborneGravityScale = 12
airGravity = 9.81 * 12 = 117.72
jumpApexTime = jumpSpeed / airGravity = 0.212 秒
jumpHeight = jumpSpeed^2 / (2 * airGravity) = 2.65 单位
```

同高度落地时间近似：

```text
t_sameHeight = 2 * jumpApexTime
```

当前地面满速跳跃的同高度水平距离：

```text
distance = groundMaxSpeed * t_sameHeight
distance = 20 * 0.424 = 8.48 单位
```

地图意义：

- 纯跳跃高差应优先控制在 2 到 3 单位。
- 不使用触手时，8 单位左右是当前纯跑跳比较合理的同高横向参考。
- 超过这个距离，应明确要求空中冲刺或触手。

## 7. 绳索圆周运动模型

单锚点绳索定义：

```text
anchor = 锚点位置
r = p - anchor
L = |r|
er = r / L
et = er 的垂直切向单位向量
```

速度分解：

```text
vRadial = dot(v, er) * er
vTangent = v - vRadial
```

绳索长度约束：

```text
如果 L > ropeLength:
    p = anchor + er * ropeLength
    如果 dot(v, er) > 0:
        v = v - dot(v, er) * er
```

这就是当前代码 `LimitRope` 的核心行为。

该模型的含义：

- 玩家可以向锚点靠近，绳索可以松弛。
- 玩家不能超过绳长继续远离锚点。
- 绳索拉紧时，远离锚点的速度会被移除，只留下切向速度和朝向锚点的速度。
- 玩家松开绳索时，当前速度就是抛出速度。

## 8. 绳长如何影响速度

不按 Q、不考虑水平输入时，绳索摆荡速度主要来自重力势能转换。

能量近似：

```text
vRelease^2 = vStart^2 + 2 * ropeGravity * dropHeight
vRelease = min(maxPlayerSpeed, sqrt(vStart^2 + 2 * ropeGravity * dropHeight))
```

其中：

```text
dropHeight = startY - releaseY
dropHeight 最大通常不超过绳长量级
```

如果玩家从锚点水平高度附近摆到锚点正下方，粗略可取：

```text
dropHeight ≈ ropeLength
vBottom ≈ sqrt(2 * ropeGravity * ropeLength)
```

当前 Player 2：

```text
ropeGravity = 9.81 * swingingGravityScale = 9.81 * 11 = 107.91
maxPlayerSpeed = 70
```

不同绳长理论底部速度：

| 绳长 | 不封顶速度 | 实际速度 |
| ---: | ---: | ---: |
| 10 | 46.5 | 46.5 |
| 20 | 65.7 | 65.7 |
| 30 | 80.5 | 70 |
| 40 | 92.9 | 70 |

速度封顶阈值：

```text
capLength = maxPlayerSpeed^2 / (2 * ropeGravity)
capLength = 70^2 / (2 * 107.91) = 22.7 单位
```

结论：

- 当前数值下，绳长在 0 到约 23 单位时会明显影响摆荡速度。
- 超过约 23 单位后，速度大多被 `maxPlayerSpeed = 70` 截断。
- 如果希望 30 到 40 单位长绳仍然体现“绳越长越快”，要降低 `swingingGravityScale` 或提高 `maxPlayerSpeed`。
- 提高 `maxPlayerSpeed` 会显著放大地图尺寸需求，不建议在样板关早期优先做。

如果希望 40 单位绳长刚好接近 70 速度，理论需要：

```text
ropeGravity = maxPlayerSpeed^2 / (2 * 40) = 61.25
swingingGravityScale = 61.25 / 9.81 = 6.24
```

所以当前 `swingingGravityScale = 11` 偏激进。

## 9. Q 牵引公式

Q 牵引是朝锚点方向施加加速度：

```text
dir = normalize(anchor - p)
aPull = dir * pullAcceleration
v = v + aPull * dt
```

当前代码使用 Force：

```text
pullForce = 300
bodyMass = 1
pullAcceleration = pullForce / bodyMass = 300
```

直线牵引达到速度上限的时间：

```text
tToMax = maxPlayerSpeed / pullAcceleration
tToMax = 70 / 300 = 0.233 秒
```

达到速度上限前的牵引距离：

```text
dToMax = maxPlayerSpeed^2 / (2 * pullAcceleration)
dToMax = 70^2 / 600 = 8.17 单位
```

从 40 单位外直拉到锚点的时间近似：

```text
如果 D > dToMax:
    t = tToMax + (D - dToMax) / maxPlayerSpeed

t = 0.233 + (40 - 8.17) / 70 = 0.688 秒
```

结论：

- 当前 Q 牵引极强，0.23 秒就能撞到总速度上限。
- 这适合“高机动爽感”，但不适合用很短空间做精密平台挑战。
- 如果地图需要更稳定的可预判移动，应该把 `pullAcceleration` 降低，或把 Q 牵引定义为短时爆发能力而不是常规位移能力。

## 10. A/D 摆荡辅助公式

当前代码在 `Swinging` 或 `Hovering` 状态中直接加水平力：

```text
aInput = Vector2.right * inputX * swingAssistAcceleration
```

当前值：

```text
swingAssistAcceleration = swingForce / bodyMass = 20
```

问题：

- 水平力不是切向力。
- 当玩家在锚点左/右/下方不同位置时，水平力对圆周运动的作用不同。
- 这会让公式推导变复杂，也会让某些角度的输入变成“推向绳外”或“推向绳内”。

建议后续改为切向辅助：

```text
et = perpendicular(er)
inputSign = sign(dot(Vector2.right * inputX, et))
aAssist = et * inputSign * swingAssistAcceleration
```

这样 A/D 只改变圆周切向速度，不直接破坏绳索约束。

这不是必须立刻改，但如果要严格定版绳索手感，应该进入后续代码改造清单。

## 11. 松绳抛出和最大可达距离

松开绳索时：

```text
releasePosition = p
releaseVelocity = v
```

之后进入空中抛体运动。

若释放速度为：

```text
vx = vRelease * cos(angle)
vy = vRelease * sin(angle)
```

落到目标高度 `targetY` 的时间：

```text
dy = releaseY - targetY
t = (vy + sqrt(vy^2 + 2 * airGravity * dy)) / airGravity
```

水平距离：

```text
rangeX = vx * t
```

同高度最大理论射程：

```text
rangeMaxSameHeight = vRelease^2 / airGravity
```

当前 Player 2 在普通空中重力下：

```text
maxPlayerSpeed = 70
airGravity = 117.72
rangeMaxSameHeight = 70^2 / 117.72 = 41.6 单位
```

但当前开启了高速弱重力：

```text
highSpeedGravityMinMultiplier = 0.55
fastAirGravity = 117.72 * 0.55 = 64.75
rangeMaxSameHeightFast = 70^2 / 64.75 = 75.7 单位
```

结论：

- 高速弱重力会把最大理论射程从 41.6 单位放大到 75.7 单位。
- 这对地图设计影响很大。
- 如果要做严格灰盒，必须明确地图按哪一种重力估算。

建议：

- 普通平台和战斗房按 `airGravity` 保守估算。
- 高速隐藏路线、高手路线、长距离飞跃才按 `fastAirGravity` 估算。
- 如果发现玩家经常越过关卡结构，应优先收紧高速弱重力，而不是随便堆墙。

## 12. 地图设计反推方法

### 12.1 普通地面段

```text
地面 1 秒距离 = groundMaxSpeed
起步到满速距离 = groundMaxSpeed^2 / (2 * groundAcceleration)
```

当前：

```text
1 秒 = 20 单位
起步距离 = 2 单位
```

### 12.2 纯跳跃平台

```text
jumpHeight = jumpSpeed^2 / (2 * airGravity)
sameHeightJumpDistance ≈ groundMaxSpeed * 2 * jumpApexTime
```

当前：

```text
跳高 ≈ 2.65
同高横跳 ≈ 8.48
```

建议：

- 纯跳高差：2 到 3 单位。
- 纯跳横跨：4 到 8 单位。
- 超过这些值就应给触手点或冲刺空间。

### 12.3 单绳摆荡段

设计步骤：

1. 选锚点到玩家路线的有效绳长 `L`。
2. 估算玩家从起点到释放点下降高度 `dropHeight`。
3. 计算释放速度：

```text
vRelease = min(maxPlayerSpeed, sqrt(vStart^2 + 2 * ropeGravity * dropHeight))
```

4. 根据释放角度计算抛体距离。

简化估算：

```text
如果释放角度接近 45 度：
    range ≈ vRelease^2 / airGravity
```

当前参考：

| 有效绳长 | 估算释放速度 | 普通空中同高最大距离 |
| ---: | ---: | ---: |
| 10 | 46.5 | 18.4 |
| 20 | 65.7 | 36.7 |
| 23+ | 70 | 41.6 |

如果使用高速弱重力，上表距离还会明显变大。

### 12.4 Q 牵引段

直拉距离 `D` 的时间：

```text
if D <= dToMax:
    t = sqrt(2D / pullAcceleration)
else:
    t = tToMax + (D - dToMax) / maxPlayerSpeed
```

当前：

```text
D = 20: t ≈ 0.40 秒
D = 40: t ≈ 0.69 秒
```

地图意义：

- 40 单位锚点不是“远距离”，当前 Q 可以很快拉到。
- 如果某段地图不想被快速跨过，不应在直线路径上给可直接 Q 拉的锚点。

## 13. 当前参数风险

### 13.1 绳索重力偏高

`swingingGravityScale = 11` 让 23 单位以上绳长很容易撞到 70 速度上限。

风险：

- 长绳和超长绳的速度差异被速度上限抹平。
- 地图中 30 到 40 单位锚点的“长绳加速感”不明显，只表现为更远可达。

### 13.2 Q 牵引过强

`pullAcceleration = 300` 让角色 0.23 秒到达 70 速度。

风险：

- 很难设计精细中短距离路线。
- 直拉会压过摆荡，玩家可能更倾向于 Q 直飞，而不是圆弧摆荡。

### 13.3 高速弱重力影响地图边界

`highSpeedGravityMinMultiplier = 0.55` 会显著提高松绳后的可飞距离。

风险：

- 按普通重力设计的墙距和平台距可能被高速玩家越过。
- 如果高速弱重力不受控，地图必须大很多。

### 13.4 水平摆荡辅助不够物理一致

当前 `swingForce` 是水平力，不是切向力。

风险：

- 不同锚点角度下，A/D 的手感不是同一个物理含义。
- 后续做精确公式时会出现解释困难。

## 14. 推荐定版方向

为了服务第一张样板关，推荐先定一个保守、可推导的版本：

```text
groundMaxSpeed = 20
groundAccelTime = 0.2
jumpHeight = 2.6 到 3.0
jumpApexTime = 0.20 到 0.25
maxFallSpeed = 60
maxCableLength = 40
maxPlayerSpeed = 70
ropeGravityScale = 6 到 8
pullAcceleration = 160 到 220
swingAssistAcceleration = 20 到 35
```

说明：

- `ropeGravityScale = 6 到 8` 能让 30 到 40 单位绳长仍有速度差异。
- `pullAcceleration = 160 到 220` 会让 Q 牵引仍然强，但不至于 0.23 秒直接封顶。
- `maxPlayerSpeed = 70` 暂时不提高，因为提高它会让地图尺寸快速膨胀。
- `highSpeedGravityMinMultiplier` 暂时不要再降低；如果越界严重，应提高到 0.7 到 0.85 或只在特定状态启用。

## 15. 后续代码落地建议

不要一次大改。建议分三步：

### 第一步：只做文档和实测

- 用当前公式测 3 个锚点长度：10、20、40。
- 记录不按 Q 的摆荡释放速度和距离。
- 记录按 Q 的到点时间和飞出距离。
- 确认当前风险是否在场景里真实发生。

### 第二步：重命名和派生参数

代码仍可保持行为不变，但 Inspector 改成更少的主参数：

- `groundMaxSpeed`
- `groundAccelTime`
- `jumpHeight`
- `jumpApexTime`
- `maxFallSpeed`
- `maxCableLength`
- `ropeGravityScale`
- `pullAcceleration`
- `swingAssistAcceleration`
- `maxPlayerSpeed`

旧参数通过 `OnValidate` 或运行时派生。

### 第三步：改摆荡辅助为切向力

把当前水平 `swingForce` 改成沿绳索切线加速。

这一步会改变手感，必须单独测试，不要和重力/拉力一起混改。

## 16. 完成定义

移动公式定版至少要满足：

- 每个状态的重力、阻尼、加速度来源可解释。
- 设计参数不超过 10 到 12 个主项。
- 每个主参数都能回答“它影响哪种地图距离”。
- 给定锚点距离、释放速度、目标平台高度，可以估算玩家是否可达。
- Unity 实测误差在可接受范围内，并记录到数值文档。

如果后续实测和公式偏差很大，以实测为准，但必须回头解释偏差来自哪里：高速弱重力、碰撞修正、绳索弯折、双绳约束、输入辅助，还是速度上限。
